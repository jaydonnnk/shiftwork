Candidate code · Concept only

Two repairs, both under C1

A · v2-a

Verifies stock on every request. Simpler broad verification and fewer ambiguity referrals, but more calls and dependency exposure.

B · v2-b

Routes by requested task, validates every stock promise, and refers ambiguous requests. Cheaper and faster, but more human referrals and a routing boundary to maintain.

These are illustrative repair directions, not supplied executable patches. The intended work is changing real learner-owned service code and visible tests, not selecting a prompt. Ordinary code may replace unnecessary AI.

Before efficiency, check validity

Mandatory task or safety failures block choice, regardless of speed or cost. A service that refuses every request helps 0 customers; avoiding wrong promises alone is not success.

Edge-state preview: Not comparable

Not comparable. Different contracts, workloads, public snapshots, starting state, model settings or ceilings invalidate an A/B comparison. Keep both records visible and design a matched fresh comparison; do not rank them.

Edge-state preview: failed or incomplete trial

Incomplete evidence. Retain the failed trial, attempted requests, failure reason and known resource use. Unknown cost stays unknown, never zero. Do not drop the trial or treat missing answers as successes; investigate before making a supported choice.

Edge-state preview: candidate changed after testing

Not tested at this version. Editing A after its trials creates a different candidate. The earlier results still describe v2-a; they do not establish eligibility for the changed code. Test the exact version before choosing it.

Edge-state preview: all-refusal control

For 12 requests: 0 helped, 12 explicit refusals. Even if no stock promise is wrong, this is not successful task completion. Keep refusals, referrals and useful answers separate.

What these tables cannot establish

Hidden expectations are never shown. Checks must be independent of learner code and model opinion. Exact execution mechanisms and scoring methodology remain for later gates. These samples are not measurements, statistical confidence or evidence that either repair works.
