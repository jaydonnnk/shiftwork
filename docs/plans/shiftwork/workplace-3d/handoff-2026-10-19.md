## Approved direction and reasoning

The destination is a real 3D workplace, not indefinite SVG-only polish. The
reference's useful mechanisms are a coherent miniature workplace, panels that
reveal relevant detail, and motion that explains recorded changes. Shiftwork's
own story is learner judgment and inherited responsibility, not watching an agent
automate a factory repair.

Three.js will be served locally as pinned browser modules alongside the existing
vanilla-JavaScript client. The workbench and labelled navigation remain HTML.
The backend, database, API and domain contracts are unchanged. This avoids an
unnecessary React migration, second server, runtime CDN or game-engine layer.
The engine release and complete imported artifact set are not yet selected or
acquired.

The scene has no fetch, command or grading authority. A pure projection supplies
public scene state, a coordinator owns graphics lifecycle, and an object pick
requests existing station navigation. One active room, explicit disposal, a
complete graphics-failure fallback and reduced-motion behavior are required.

  at 1280px, 640px and 390px without horizontal overflow and with full-width
  notices. Desktop layout A/B and mobile Northline screenshots were inspected.
  Northline's static Acceptance anchor focused the workbench at y=16px on 390px.
  This does not fix production Northline or prove a 3D renderer.
- The original hosted study measured a notice/grid defect at 1280 by 720: a 926px
  notice column, a 354px room column and workbench y=875px. Production remains
  unchanged. The first mockup repeated a paragraph-width cap and was corrected.
- `latest_run` may be an experiment or legacy run. Its completion is never a
  business-success signal. Operational consequences require their public ledger
  and incident links, purpose and evidence labels.
- A browser refresh joins several requests; client generation checks do not
  make those reads an atomic server snapshot. Inconsistent links stay unknown.
- `refresh()` increments generation and calls `clearData()` on normal polls.
  Routine loading preserves the last accepted presentation reference for diffing.
  It does not reset continuity or authorize stale workbench actions. Actual
  errors, mismatched joins, historical navigation and board/shift changes reset
  continuity; reloading history never stages fresh success animations.
- Polling misses intermediate steps. No invented per-tool trace, model thoughts,
  completion percentages or consequences may fill the gaps.
- Existing package checks fetch three named assets only. They do not verify a
  new engine's nested import graph. Production modules need the HTTP server;
  standalone Gate 1 storyboards also open directly from disk.
- The first mock generator used an optional pathlib argument unsupported by the
  system Python. Byte writes corrected it. One approval patch used an absent
  anchor and was rejected without partial writes. Incidents are in MISTAKES.md.
